# Deviation register

§18: *a deviation register instead of pretending the codebase is clean.* Every row is a place this
repo knowingly departs from [`blueprint/ARCHITECTURE-BLUEPRINT.md`](blueprint/ARCHITECTURE-BLUEPRINT.md),
with the reason and the answer §18 asks for: may another repo copy this?

Rows 1 and 2 are referenced by name from the enforcement layer, so their numbers are stable:
`.dependency-cruiser.js` cites row 1 in the header and in `no-infrastructure-from-support`,
`scripts/audit-structure.js` cites it in `support-holds-no-injection`, and `.gitlab-ci.yml` cites
row 2.

There are two documents by this name and they are not the same thing: the blueprint ships its own
template at [`blueprint/DEVIATION-REGISTER.md`](blueprint/DEVIATION-REGISTER.md), and this file is
this repo's. A citation of the form "DEVIATION-REGISTER row 1" in `.dependency-cruiser.js` or
`.gitlab-ci.yml` means a row of **this** file.

## Adding a row

A row is not a suppression. §18 makes it the place a deliberate departure is written down, so it must
carry a reason and an answer about copying; a deviation with neither is an oversight that has learned
to dress up. If a departure can be removed by a decision the owner has not yet made, the row says so
and names who decides.
