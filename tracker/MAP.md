## Destination

A complete, implementable **spec** for a production-grade, fully-custom admin panel (separate app) plus the backend that powers it — covering dynamic products, page-builder pages with custom slugs, navigation/mega-menu management, blog, orders/accounts/inventory, Iranian payment gateway, and marketing features. Building starts as a separate effort once this map has no open tickets.

## Notes

- **Domain:** Iranian home-appliance e-commerce store (DATEES-brand ovens, hoods, cooktops, sinks). Currency: TOMAN. Customers are in Iran — every third-party service must be reachable from Iran without a VPN for *customers*; the owner can reach global services for now.
- **Current state of the store app:** React 19 + Vite + Tailwind 4 + react-router 7. Deployed via `gh-pages` to `hadixel.github.io` (**retires hard-cut at go-live** per deployment decision). Products are hard-coded in `src/assets/assets.js`; cart and orders live only in `ShopContext` browser state (lost on refresh). No backend of any kind yet.
- **Locked constraints (from charting):**
  - Fully **custom build** — no headless CMS, no BaaS as the core (owner's explicit choice).
  - Admin panel is a **separate React app** sharing one API with the store.
  - Hosting: **Vercel** behind **`kmodern.ir`** (store+API) / **`admin.kmodern.ir`** (admin); media on **ParsPack** free-tier S3 (amends earlier ArvanCloud lock — see deployment decision).
  - Scope is maximal: content, orders, payments, marketing — "all of it".
- **Skills every session should consult:** `/grilling` + `/domain-modeling` for HITL tickets; `/to-spec` when the final spec-assembly ticket graduates from the fog.
- **Tracker conventions (local markdown):** tickets live in `tracker/tickets/NNN-slug.md`, one file per ticket. Frontmatter: `title`, `labels` (`wayfinder:research|prototype|grilling|task`), `status` (`open|closed`), `assignee` (empty = unclaimed; set it **before** working a ticket), `blocked-by` (list of ticket file names; unblocked when every listed ticket is `closed`). Resolution is appended under `## Resolution`, then `status: closed`. Research assets live in `tracker/assets/`.
- **Frontier query:** `open` tickets, empty `assignee`, all `blocked-by` entries closed.

## Decisions so far

- [Model discounts and promotions](tickets/018-discounts-promotions.md) — PERCENT/FIXED/FREE_DELIVERY only. Scope: ALL / PRODUCTS / CATEGORIES / COLLECTIONS. Activation: COUPON or AUTOMATIC. Stacking: one merch discount + FREE_DELIVERY possible; coupon beats automatic. Usage limits: start/end, min subtotal, max uses total/customer, status. Order recording: `discountAmount` + snapshot + invoice shows تخفیف; lines stay list price; FREE_DELIVERY alone shows ۰ delivery note. Banner block carries `discountId` / code; application server-side at cart place.
- [Design the admin panel information architecture](tickets/017-admin-panel-ia.md) — Sidebar: داشبورد · سفارش‌ها · کاتالوگ · محتوا · مشتریان · بازاریابی · تنظیمات. Dashboard = new-order / low-stock / drafts queues + today strip (on-load). Full-page list→detail; bulk publish/archive on products/posts; orders export-only. Settings tabs: store/shipping/payments(C2C only)/inventory/notifications/account/audit. Page-builder + blog full-page editors with preview token; nav tree; media library + modal pickers. Route inventory locked; visual prototype skipped.
- [Model customer & admin notifications (order and account events)](tickets/016-customer-notifications.md) — Customer SMS only on OTP + placed/paid/confirmed/shipped/delivered/cancelled; skip processing & payment-failed. Admin = in-app queues only (no admin SMS; `admin.alertMobile` reserved). 7 Kavenegar Lookup templates (`otp`, `orderplaced`, `orderpaid`, `orderconfirmed`, `ordershipped`, `orderdelivered`, `ordercancelled`). Transactional never opt-out; marketing uses `smsMarketingConsent` default false. `NotificationLog` for audit; `sendOtp` / `sendTransactional` abstraction.
- [Define deployment, domains, and environments](tickets/012-deployment-environments.md) — Prod: `kmodern.ir` store+API, `admin.kmodern.ir`, `www`→apex; staging: `staging.kmodern.ir` + `admin.staging.kmodern.ir`; PR previews on staging data. Two Vercel projects; one Neon project (`production`/`staging` branches). Secrets in Vercel env per scope. **Media: ParsPack free-tier S3** (amends ArvanCloud) + immutable keys; Neon PITR on prod. Shaparak/live کد درگاه **at cutover** on apex only; sandbox until then. Hard-cut gh-pages at go-live.
- [Research Iranian SMS providers (OTP + order notifications)](tickets/015-research-iran-sms.md) — **Kavenegar** recommended (`/verify/lookup.json` + official Node SDK, shared خط خدماتی, multi-token templates). Runners-up SMS.ir (optional IP lock, sandbox) and Ghasedak (hard IP bind). Avoid Melipayamak as primary on Vercel (`-109` allowed-IP). All need pre-approved پترن; generate OTP in-app.
- [Research Iranian shipping rate APIs for checkout quotes](tickets/019-research-iran-shipping-rates.md) — **Postex** recommended (`POST /api/v1/shipping/quotes`, multi-carrier incl. IR_POST/CHAPAR/MAHEX). Runner-up Tapin (Iran Post only, **≤30 kg**). Tipax fits heavy weights but no public rate API. Default post cap 0 / باربری-first stays justified for appliance ovens.
- [Design the checkout and payment flow](tickets/011-checkout-payment-flow.md) — Pay: Zarinpal ONLINE + CARD_TO_CARD + COD (LOCAL/Kerman only, max total default 50M). Auth wall at Place (OTP first, later OTP/password); address may be filled logged-out. Ship auto: Kerman→LOCAL, else weight≤cap→POST, else BARBERI; category `weightKg` required; post cap default 0 (post off until enabled). Fees: local FREE\|FLAT\|FREIGHT_COLLECT; post API quote + fallback (default 0=unavailable); باربری storefront always پس‌کرایه (admin fee notes-only). Holds: online 30m / C2C 48h configurable; one AWAITING per customer; ONLINE/C2C reserve until PAID, COD commits at place. Zarinpal: create+reserve first, API callback verify, reconcile job, never resurrect after cancel; admin force-PAID with note. C2C: receipt optional, ≥total to confirm, SMS link + phone/order lookup. Switches ONLINE↔C2C only. Fee/total frozen at place. Two PDFs (invoice + packing). No VAT this build. Post provider → [019](tickets/019-research-iran-shipping-rates.md).
- [Decide admin authentication, roles, and security model](tickets/010-admin-auth.md) — Vetted auth library (**not** hand-rolled) with **server-side sessions** in Postgres behind an httpOnly/Secure cookie, giving instant revocation. **Fully separate realms**: an `AdminUser` + admin-subdomain login (email + password) vs the phone-OTP `Customer` from 009 — no privilege path between them. **Single admin role for now**, with a `role` field and a central policy helper reserved so Owner/Editor/OrderManager can land later without a migration. **2FA declined** for this build (password-only) — compensated by a strong-password policy, per-IP/per-account **rate limiting + lockout**, and an **admin audit log**; schema left TOTP-ready and the residual risk recorded as the spec's largest security gap. Captcha and IP allowlist declined. Auth-scoped secrets via Vercel encrypted env; the broader secret/env inventory belongs to 012.
- [Model orders, customer accounts, and inventory](tickets/009-orders-accounts-inventory.md) — Phone-first `Customer` (unique mobile) with guest checkout; OTP-primary login + optional password; structured province/city addresses (multiple, snapshotted onto the order). Orders carry two independent status dimensions — admin-driven `fulfillmentStatus` (pending→confirmed→processing→shipped→delivered, + cancelled/returned) and gateway-driven `paymentStatus` (awaiting→paid→refunded/failed) — with snapshotted line items, a per-Jalali-year padded order number (`1404-000123`), and a status-event timeline. Inventory **reserves on order, commits on payment, releases on failure/timeout** (COD commits at placement; cancelling a paid order restocks); per-variant low-stock threshold + admin view. Admin orders screen: search/filter, status-change + timeline + SMS, invoice/packing-slip PDF, manual order entry, cancel+refund. Returns = cancel + mark-refunded, no RMA. Hands 011 the payment fields; graduates an SMS-provider research ticket + a notifications ticket.
- [Model the blog — posts, editor, and listing](tickets/007-blog-model.md) — A Post is its own entity, **not** a page-builder page: a prose-first rich-text (TipTap-style) `body` stored as validated JSON, with inline embeds — product card/grid, image gallery, video, callout/quote — that reuse the component Zod schemas from 008/005. Video supports Aparat **and** YouTube, but YouTube is flagged as filtered-inside-Iran (Aparat default). Own lightweight admin-managed `BlogTag` taxonomy (separate from the product tree); single configurable store byline; comments deferred behind a per-post `commentsEnabled` flag; lifecycle draft/published/archived + optional scheduled `publishAt` (visibility gated by query, no cron); listing has pagination, tag filter, a pinned featured post, and Postgres full-text search. Unblocks the SEO ticket.
- [Model navigation — navbar items, subcategories, mega menus](tickets/006-navigation-model.md) — Hybrid: nav is its own admin-built, ordered tree of items that *link to* categories/pages/blog/collections/external URLs (or act as non-link group headers), never auto-derived. A `Menu` is keyed by location (header/footer/mobile; mobile falls back to header). Per top item the panel is a flat dropdown or a mega panel (grouped link columns + optional clickable promo image); a column can auto-list a category node's live children (per-item toggle, mixable with static links). Depth capped at 3 levels; `visible`/`mobileVisible`/`sortOrder` mirror the block model; mobile renders as an accordion with promo media hidden. One Zod schema drives form + API + renderer; a deleted/unpublished target renders empty, not an error.
- [Model dynamic pages and the page-builder system](tickets/005-page-builder-model.md) — Ordered JSONB block list per Page (draft/published columns); system pages (Home/About/Contact) + custom {slug} pages, transactional routes keep editable zones only; structured list-and-preview admin editor (no live canvas); one Zod schema per component in a shared package drives form + API validation + renderer.
- [Propose the e-commerce component catalog](tickets/008-component-catalog.md) — Approved: 23 components in 3 tiers (9 core incl. Hero/Product Grid/Banners/USP row; 8 conversion incl. sliding strip, FAQ, countdown; 6 nice-to-have incl. comparison table, custom HTML). Instagram embeds, live chat, and popups cut. Standard props on every block; every image can carry a link.
- [Model the product domain (categories, variants, specs, stock)](tickets/004-product-model.md) — Color = full variant (own price/stock/SKU/images); admin-managed arbitrary-depth category tree; hybrid specs (category-defined fields + free-form extras); per-variant stock with backorder toggle; draft/published/archived lifecycle; slug URLs; named collections replace the bestSeller flag.
- [Research Iranian payment gateways and their integration constraints](tickets/002-research-iran-payments.md) — Zarinpal recommended (official Node SDK, sandbox, works behind a registered custom domain); runners-up Zibal, IDPay. Shaparak binds the gateway to one registered domain (not a hosting country), but some gateways block foreign server IPs at the API layer — a real constraint on Vercel-hosted APIs.
- [Choose the backend stack and database](tickets/001-backend-stack.md) — Everything on Vercel behind the owner's custom domain: Next.js store+API and a second Next.js admin app in a monorepo; Postgres (Neon) + Prisma; media on ArvanCloud; payment gateway locked to Zarinpal as a consequence.
- [Research media storage and delivery reachable from Iran](tickets/003-research-media-storage.md) — ArvanCloud Object Storage + CDN (S3-compatible, in-Iran PoPs, Rial billing); runners-up Liara, ParsPack. Foreign options (Cloudinary, Vercel Blob, S3+CloudFront, B2+Cloudflare) blocked in one direction or the other by sanctions/filtering.
